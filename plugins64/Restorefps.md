## Description

RestoreFPS reverses the kind of blending generated by [ConvertFPS](https://avisynthplus.readthedocs.io/en/latest/avisynthdoc/corefilters/fps.html) and restores the original frame rate. It works on any regular blend pattern whose weights are known, including the types mentioned by scharfis_brain [in this thread](https://forum.doom9.org/showthread.php?s=&threadid=89266).

The plugin also contains a few related tools:
- **RestoreFPSIVTC** reverses a frame-duplication telecine followed by a ConvertFPS-style blend.
- **ThresholdIncreaseFPS** increases the frame rate by blending, but only when the two frames' weights are close enough.
- **Reblend** helps measure blend weights by hand.
- **TelecineConvertFPS** generates test clips for RestoreFPSIVTC.

## Requirements

- AviSynth+ (x86 or x64). Frame property passthrough needs interface version 8 (AviSynth+ 3.6 or later); on older versions the plugin still works, but output frames carry no properties.
- Supported color formats: 8-bit planar YUV (YV12, YV16, YV24, YV411, Y8)

## Syntax and Parameters

All parameters are positional (unnamed) and have no defaults, so they must all be given.

### RestoreFPS

```
RestoreFPS (clip, float fps, float phase)
```

- *clip*: the blended input clip.
- *fps*: the 'underlying' frame rate of the input clip. The clip's actual frame rate is higher because of the blending. RestoreFPS reverses the blending and outputs a clip at *fps*. It must be greater than 0 and lower than the clip's frame rate.
- *phase*: a number between 0 and 1 that gives the relative displacement of the old and new clips (see the examples). It must be 0 or more.

The original documentation says *fps* must be more than half the clip's frame rate. The author removed that limit in a later version. Below half, the output is very sensitive to *phase*: if it is even slightly off, some blends slip through.

### RestoreFPSIVTC

```
RestoreFPSIVTC (clip, float fps, float phase, int telecine)
```

Reverses the pattern *frame-duplication telecine → ConvertFPS-style blend*, for example 23.976 → 29.97 (a frame repeated every 4) → blended to 25.

- *fps*: the frame rate **after** telecine and before blending (e.g. 29.97). The output frame rate is *fps* × 0.8. That must be lower than the clip's frame rate, and *fps* must be greater than 0.
- *phase*: 0.0 to 1.25, as documented by the author. It must be 0 or more.
- *telecine*: 0 to 4. This selects which frame of each group of 4 is duplicated: 0 = `SelectEvery(4,0,0,1,2,3)`, 1 = `SelectEvery(4,0,1,1,2,3)`, and so on. It must be 0 or more.

The author considered this function a "red herring": it works on synthetic clips but failed on real samples.

### ThresholdIncreaseFPS

```
ThresholdIncreaseFPS (clip, float fps, float threshold)
```

Increases the frame rate like ConvertFPS, but only blends two frames when the smaller of their two weights is at least *threshold*. Otherwise it copies the nearer frame.

- *fps*: the new frame rate. It must be at least the clip's frame rate; decreasing is not supported.
- *threshold*: a fraction, not a percentage (e.g. 0.45).
  - 0 always blends, like ConvertFPS.
  - 0.5 never blends, like ChangeFPS.
  - With 0.3, a 20/80 blend becomes a copy of the 80% frame.

### Reblend

```
Reblend (clip, float weight)
```

Output frame *n* = (1 − *weight*) × frame *n*−1 + *weight* × frame *n*+1. Frame 0 is passed through unchanged, and the output is one frame shorter than the input.

It is meant for finding blend weights, especially in animation where frames are duplicated. Use `Subtract(c, Reblend(c, w))` and adjust *w* until the blended frame cancels out. For example, frame 4616 ≈ 0.47 × 4615 + 0.53 × 4617 cancels at *w* = 0.53.

### TelecineConvertFPS

```
TelecineConvertFPS (clip, float fps)
```

Test-clip generator: duplicates the first frame of every 4 (`SelectEvery(4,0,0,1,2,3)`), then blends to *fps* like ConvertFPS. The output can be reversed with `RestoreFPSIVTC(clipfps × 1.25, 0.0, 0)`. *fps* must be greater than 0.

### Test

Undocumented debug function left in by the author. It writes `log.txt` to the working directory. Not for normal use.

## Examples

**Round trip.** In the clip below, the start of the input corresponds exactly to the start of an original frame, so *phase* is 0:

```
AviSource("film.avi")     # progressive, 8-bit planar YUV
AssumeFPS(24000, 1001)
ConvertFPS(25)
RestoreFPS(24/1.001, 0.0)
```

**Finding the phase.** If the blended clip is trimmed (say `Trim(10,0)`), the converted clip is 'slid' relative to the original, and *phase* has to be guessed. This function helps:

```
function phase(clip c, float phi)
{
c
RestoreFPS(24/1.001, phi) # set the appropriate frame rate here

# trim here if desired

a=SelectEvery(6,0)
b=SelectEvery(6,1)
c=SelectEvery(6,2)
d=SelectEvery(6,3)
e=SelectEvery(6,4)
f=SelectEvery(6,5)

StackHorizontal(a,b,c,d,e,f)
ReduceBy2()
StackVertical(last, Trim(1,0), Trim(2,0), Trim(3,0), Trim(4,0), Trim(5,0))
Trim(0,-1).Loop(0,1000)
Subtitle(String(phi, "%f"))
}

# insert source clip here

Animate(0, 100, "phase", 0.0, 1.0)
Trim(0, 100)
```

Save the output and scrub through it in VirtualDub to find a phase that looks correct.

**Telecine plus blend:**

```
AssumeFPS(24000, 1001)
SelectEvery(4,0,1,1,2,3)             # 29.97
ConvertFPS(25)
RestoreFPSIVTC(30/1.001, 0.0, 1)     # back to 23.976
```

## Notes

- **Field blending:** if fields rather than whole frames are blended, separate the fields and process each one on its own. The top and bottom fields may need phases that differ by 0.5.
- **Wrong fps:** if *fps* is slightly wrong, the filter works in one region and gets steadily worse as it drifts away from it.
- **Cuts and dropped frames** break the pattern. Each section needs its own *phase*.
- **Start of the clip:** the first few output frames may look odd. This is an edge effect of the method.
- **Frame properties** are passed through; the plugin never writes any. A frame that RestoreFPS outputs unchanged keeps its own properties. A blended or reconstructed frame takes its properties from the input frame with the largest weight. Properties such as `_DurationNum`/`_DurationDen` are therefore **not** updated to the new frame rate.
- **Multithreading:** all functions are `MT_NICE_FILTER`.
- The output frame rate is stored as a close fraction rather than the exact ratio (e.g. not exactly 24000/1001). Use `AssumeFPS` afterwards if the exact value matters.

See `CHANGELOG.md` for the differences from the original AviSynth 2.5 plugin.
